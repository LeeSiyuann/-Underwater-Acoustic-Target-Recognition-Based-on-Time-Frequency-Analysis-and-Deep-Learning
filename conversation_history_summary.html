4. 涉及的代码撰写与修改场景

4.1 模型定义：deep_learning_models.py

修改目的

统一承载单流模型定义，覆盖 CNN、ResNet、RNN、LSTM、Transformer，并通过 get_model() 对外提供模型工厂接口。

关键演化

  • 最早按需求加入多类网络。
  • 在环境确认后改回 torchvision.models 风格 ResNet。
  • 加入 ResNet34、ResNet50、RNN。
  • 曾扩展 ViT/Swin，后按用户要求删除。
# 使用 torchvision 官方 ResNet，并适配单通道声谱图输入
class ResNetBase(nn.Module):
    def __init__(self, model_func, num_classes=4, input_channels=1):
        self.model = model_func(weights=None)
        self.model.conv1 = nn.Conv2d(input_channels, 64, kernel_size=7, stride=2, padding=3, bias=False)
        self.model.fc = nn.Linear(self.model.fc.in_features, num_classes)

这段逻辑的核心意义在于：既复用成熟的残差网络结构，又让自然图像网络适配单通道声谱图输入，是项目从“通用视觉模型”向“声学时频图模型”迁移的关键一环。

4.2 核心训练主程序：train_comparison.py

这是全项目最重要的主干脚本。它承接了绝大多数需求变更，也是后续所有结果文件的主要来源。其主要修改场景可归纳为：

  • 引入多模型训练循环，按特征文件和模型名称形成双层遍历。
  • 根据模型类型自动切换 2D 输入与序列输入。
  • 扩展多维评估指标：Accuracy、Precision、Recall、F1、ROC-AUC。
  • 输出训练日志 CSV、训练历史图、混淆矩阵、PR 曲线。
  • 记录显存峰值，生成 gpu_memory_usage.csv。
  • 根据特征名动态设置 batch size；对 STFT 设置特殊限制。
  • 根据 CPU 核数设置 num_workers，提升数据供给效率。
  • 移除文本文件日志，仅保留控制台输出和结构化 CSV。
# 按特征动态调整 batch size，避免 STFT 爆显存
current_batch_size = STFT_BATCH_SIZE if "stft" in feature_name.lower() else DEFAULT_BATCH_SIZE

# 针对 22 vCPU 环境提高数据加载吞吐
cpu_count = multiprocessing.cpu_count()
num_workers = min(16, cpu_count)

该脚本最终产生的训练产物是按“每个模型 × 每种特征”命名的完整文件簇，这构成了后续论文分析的实证基础。

4.3 显存分析与推荐 batch size：calculate_recommended_batchsize.py

该脚本来自一个明确的后处理需求：用户不希望修改训练脚本，只想根据历史显存记录反推更合理的 batch size。它的角色不是训练，而是“实验运营优化器”。输出文件为 recommend_batchsize.csv。

4.4 断点恢复：resume_training.py

当 ResNet50 + STFT 训练阶段 OOM 中断后，为满足“不要修改现有主脚本、不要从头再跑”的要求，专门编写了断点续训脚本。它的工作机制包括：

  • 扫描已有 training_log_*.csv，识别已经完成的任务。
  • 重构已完成任务的最终指标，恢复到汇总表中。
  • 对未完成任务继续训练。
  • 在 STFT 场景进一步使用更保守的 batch size。
# 续训脚本内对 STFT 采取更严格的 batch size 限流
DEFAULT_BATCH_SIZE = 2048
STFT_BATCH_SIZE = 128

该脚本编写后用户发现遗漏了 matplotlib.pyplot 导入，后续又做了一次针对性修复。
